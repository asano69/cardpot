以下、Phase 2 を完了させるための段階的実装計画です。


## 前提のおさらい（plan.md より）

- Lezerはノード型を動的合成できないため、`decos` の組み合わせごとに新しい型を作るのではなく、**各装飾文字を個別のノード型として持ち、同じ range を入れ子（nest）にして表現する**。
- 入れ子の一番外側だけが実際の開始/終了マーカー（`isMark` 付き）を持つ。内側のラッパーはマーカーを持たず、`revealStyle` クラスだけを乗せる。
- ネストの順序は固定の静的リスト（例: `[{char:"*",node:"Bold"},{char:"/",node:"Italic"},...]`）で決める。
- 中身は再帰的にインラインパースする（`[* [Link]]` の `[Link]` も解釈させる）。

## ステップ1（実施済み・前回分）
`rules/bold.ts` を `[*+ text]`（`*` の個数任意）まで一般化。単一ノード `Bold` のまま、ネスト機構はまだ導入しない。

## ステップ2: `/`（Italic）を単独で足す（ネストなしで確認）
`*` の次に `/` を単独で扱えるようにし、**まだ組み合わせ（`*` と `/` の同時使用）は要求しない**段階。

- `rules/decoration.ts`（新設）に、`bold.ts` と同じ構造で `parseItalic` 相当を実装するのではなく、**この時点で汎用ディスパッチャの骨格だけ作る**：
  - `MARKS: {char, node}[]` を定義（`*` → `Bold`, `/` → `Italic`）。
  - `[` + 1文字の deco char（まだ複数文字の組み合わせは考えない）+ スペース + 中身 + `]` を判定。
  - 中身は `cx.parser.parseInline(...)` で再帰パース（これは `bold.ts` にはまだ無い機能なので、ここで導入）。
  - 単一マークなので、この段階ではネスト用の内側ラッパーは生成しない（マーク数1個 = 今までの Bold と同じ形）。
- `index.ts`:
  - `defineNodes` に `Italic`, `ItalicMark` を追加。
  - `revealStyle`/`isMark` に登録。
  - `parseInline` 配列の `CardpotBold` をこの新しい汎用パーサに差し替える（`*` と `/` の両方をカバー）。
- `editorTheme.ts` に `.cm-italic { font-style: italic; }` を追加。
- テスト:
  - `[* bold]` → 引き続き `Bold` になること（既存回帰）。
  - `[/ italic]` → `Italic` になること。
  - `[* [Link] text]` のような中身のネストされた WikiLink/Code が壊れず再帰パースされること（bold.ts にはまだ無かった検証）。
  - `*` の個数一般化が `/` 側にも同じロジックで効くこと（例えば将来 `//` のようなケースが来ても壊れないか、あるいは `/` は個数を意識しない仕様かを cosy 側で確認 — cosy の `DECO_CHARS` には `*` の特別扱い（連続数→強度）以外は単純な「1文字以上の同種文字の並び」として扱われるため、`/` も連続可とする）。

## ステップ3: `*` と `/` の同時使用（本格的なネスト機構の導入）
ここで初めてネスト機構が必要になる。

- `rules/decoration.ts` を拡張:
  - `decos` 文字列（例: `"*/"`）から `MARKS` 配列と照合し、**登場した順ではなく MARKS の固定順**でアクティブなマークを抽出する。
  - 一番外側（`MARKS` の先頭に近い方、例えば `Bold` を外側固定）だけが `BoldMark`/`ItalicMark` の開始・終了マーカーを持つ。
  - 内側ラッパーはマーカー無しで、同じ range を再度ラップして `revealStyle` クラスだけ乗せる（plan.md のスケッチ通り）。
  - 中身は最内側でのみ実際に `parseInline` される。
- テスト:
  - `[*/ text]` → `Bold(Italic(...))` のようなネスト構造になること（`.toString()` で確認）。
  - 出現順序が入れ替わっても（`[/* text]` のように書いても）canonical order で `Bold` が外側になること。
  - 単一マークのみのケース（ステップ2で追加したテスト）が壊れていないこと。
  - `syntaxReveal.ts` 側でカーソルが触れていない時に外側のマークだけ隠れ、内側ラッパーは常時スタイルが乗っている状態になること（手動確認 or 可能ならユニットテスト）。

### 作業報告
**補足:**
- `syntaxReveal.ts` / `editorTheme.ts` / `index.ts`（`defineNodes`, `revealStyle`, `isMark`）は変更不要です。ノード型（`Bold`/`Italic`）自体は既に登録済みで、`syntaxReveal.ts` は木を走査して各ノードに `revealStyle` を適用する汎用実装のため、ネストした `Italic` にも自動的に `.cm-italic` が乗ります。
- 内側の `Italic` はマーク（`isMark` 要素）を持たないため、`syntaxReveal` は隠す対象を見つけず常に表示されたままになり、plan通りの「一番外側だけカーソルで reveal/hide」という挙動になります。
- Phase 2 のスコープ通り、対応する記号は引き続き `*`（Bold）と `/`（Italic）のみです（`-`/`_` など他の DECO_CHARS への拡張は見送り済み）。
